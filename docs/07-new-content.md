# 새 콘텐츠 추가 (블록 · 가구 · 아이템 · 사운드)

NarewStudio의 **새 리소스 추가** 화면(`studio/creator.py`)이 하는 일과, 그 근거가 된 엔진 한도를 정리한다.
한도는 REA로 `IsletEngine_x64.dll`의 표 로더를 읽어 확인했다. 새 블록·가구는 2026-10-13 게임에서 동작을 확인했다 (5장).

## 1. 엔진이 읽는 표

| 표 | 위치 | 키 | 비고 |
|---|---|---|---|
| 아이템 | `XML\item_table.xml` | `<item id>` | `CItemTable::GetItem`이 1–19999만 받는다 |
| 블록 | `XML\brick_table.xml` | `<brick id>` | 1–254 (0 = 빈칸, 255 = 충돌 전용) |
| 설치물(가구) | `XML\product.xml` | `<product id>` | `IProductManager::Load`가 포인터 1024개(0x2000바이트) 배열을 범위 검사 없이 쓴다 → **1–1023만 안전** |
| 제작 | `XML\crafting.xml` | `<craft id>` | `ParsingNode`가 2599(0xA27)보다 큰 번호를 버린다 |
| 문자열 | `Language\string.xml` (게임 폴더의 낱개 파일) | `<string table index>` | 14개 언어 태그 `kor eng cha rus thi jpn vn ph tw id es pt de fr` |
| 날씨·시간 | `XML\sky.xml`, `Sky\sky.xml` | `<sky time weather>` | 두 벌이 있어 둘 다 고친다 |
| UI 효과음 | `Gui\sound.xml` | `<sound type>` | |

연결 규칙:

- 블록 아이템의 번호는 블록 번호와 같다 (`<type value="Brick">`). 아이콘은 `Item\Icon\brick\icon_brick_NNN.png`.
- 그 밖의 아이템 아이콘은 `Item\Icon\craft\<icon>` (64×64 PNG).
- 설치물 아이템은 `<type value="Product">`이고 `<model>`에 설치물 번호를 적는다. 설치물의 모델은 `"Object\" + <model>`.
- 모델의 재질 텍스처는 "모델 폴더 + 상대 경로"로 읽는다 (`IMaterial::LoadTexture`). `:`로 시작하는 작업자 PC 경로는 읽지 않는다.
  그래서 하위 폴더(`Object\KEH\…`)의 모델을 `Object\`로 복사할 때는 바꾸지 않은 텍스처의 경로를 `KEH\…`로 고쳐 원본을 계속 가리키게 한다.
- 이름은 `string table="item_name"`, 설명은 `string table="item"`에 아이템 번호로 넣는다. 아이템 표의 `<name>`(영문)·`<e_name>`(한글)도 채운다.
- `<stat disassembly>`는 분해할 때 재료를 돌려주는 제작 번호다. 게임 표에서는 546개 아이템이 "1개를 만드는 자기 레시피"를 가리키고,
  블록 아이템은 모두 0이다. 틀을 그대로 두면 틀 아이템의 재료가 나오므로, 도우미는 자기 레시피(1개를 만들 때만) 또는 0으로 바꾼다.

## 2. 번호 고르기

| 종류 | 쓸 수 있는 번호 (2026-10 게임 기준) | 규칙 |
|---|---|---|
| 블록 | 149, 160–170, 192–239 (60개) | 171–191은 옛 프리팹이 쓰고 있어 피한다 |
| 설치물 | 58, 59, 597–599, 942–1023 (87개) | 화면은 942 이상을 먼저 보여 준다 (공식 추가분과 덜 겹치게) |
| 아이템 | 19300–19999 (모드용 권장 구간) | 블록 아이템만 예외(블록 번호와 같음) |
| 제작 | 2599부터 아래로 | 공식 레시피는 낮은 번호부터 늘어나므로 위에서부터 쓴다 |

게임 업데이트로 같은 번호가 공식 콘텐츠에 쓰이면, 모드 매니저의 표 병합에서 모드 쪽 항목이 공식 항목을 덮는다.
NarewStudio는 열 때마다 빈 번호를 다시 계산하므로, 업데이트 뒤에는 모드를 다시 열어 겹치는 번호가 없는지 확인한다.

## 3. 표 병합 패치 (`merge/`)

모드는 표를 통째로 담지 않고, 바꿀 항목만 담은 패치를 `merge/<표 경로>`에 둔다 (UTF-8):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<merge>
  <brick id="149"> … 항목 전체 … </brick>
  <item id="149"> … </item>
</merge>
```

- 항목은 표마다 위 1장의 "키"로 찾는다. 같은 키가 있으면 그 항목을 통째로 바꾸고, 없으면 표 끝에 더한다.
- 원본 표의 나머지 글자(주석·들여쓰기·인코딩 EUC-KR·줄바꿈 CRLF)는 그대로 둔다. 원본 인코딩에 없는 글자는 `&#NNNN;`으로 쓴다.
- 1장에 없는 표는 `id` 속성을 키로 쓴다.
- 구현: `narew/xmlmerge.py` (`apply_bytes`). NarewStudio는 화면에 병합 결과를 보여 주고, 모드 매니저는 적용할 때 병합한다
  (우선순위 낮은 모드부터, 같은 항목은 위쪽 모드가 이김).

## 4. 각 도우미가 만드는 것

| 도우미 | 파일 (`files/`) | 표 병합 (`merge/`) |
|---|---|---|
| 새 블록 | `terrain.png`(빈 칸에 텍스처), 필요하면 `terrain_specular.png`, 블록 아이콘 | `brick_table`(틀 블록 복사 + 타일 번호), `item_table`(블록 아이템), `string.xml`, 레시피 |
| 새 가구 | `Object\<이름>.nwmt` (+ 바꾼 텍스처 `<이름>_diffuse.png` 등), 아이콘 | `product`(틀 설치물 복사 + 모델 + 크기), `item_table`, `string.xml`, 레시피 |
| 새 아이템 | 아이콘 | `item_table`(틀 아이템 복사), `string.xml`, 레시피 |
| 새 사운드 | 소리 파일 | `XML\sky.xml`·`Sky\sky.xml`의 `<bgm>`, `Gui\sound.xml` |

블록 아이콘은 위·옆 텍스처로 정육면체를 그려 자동으로 만든다. 가구 아이콘은 이미지 파일이나 3D 미리보기 캡처(배경 투명 처리)로 만든다.

## 5. 인게임 확인

**2026-10-13 확인됨**: 테스트 모드 "나루 테스트 콘텐츠"(새 블록 #149 + 새 가구 #942/아이템 #19300, 흙으로 만드는 손 제작
레시피 2599/2598)를 NarewModManager로 Steam 설치본에 적용하고 게임에서 동작을 확인했다. 즉 팩 패치 + 표 병합 + `Language\string.xml`
덮어쓰기 경로로 새 블록·가구·레시피·이름이 들어간다.

**2026-10-13 확인됨 (사운드)**: 테스트 모드 "나루 테스트 사운드"로 UI 효과음 `click`을 새 파일 `Sound\mod\narew_click.wav`
(44.1 kHz 16비트 스테레오 WAV)로 바꿨더니 게임에서 버튼 소리가 바뀌었다. 즉 `Gui\sound.xml` 표 병합과, 팩에 없던 새 소리 파일을
`sound.pack`에 추가하는 경로가 동작한다.

아직 따로 확인하지 않은 것:

1. "새 아이템" 도우미로 만든 일반 아이템(음식·물약 등)의 효과.
2. 날씨·시간 배경음(`sky.xml`의 `<bgm>`) 교체.
3. 멀티 플레이에서 서버가 새 아이템을 받아들이는지.
