# 캐릭터 교체 — 다른 3D 모델을 아일렛 캐릭터로

> NarewStudio **모델 뷰어 → 🧍 캐릭터 교체** 또는 에이전트 도구 `character_swap`.
> 코드: `narew/charswap.py`(리타깃), `narew/scene3d.py` + `fbx.py` / `scene_gltf.py` / `scene_obj.py` /
> `scene_pmx.py`(읽기), `studio/svc_charswap.py`(모드 프로젝트에 쓰기), `studio/ui/charswapdlg.py`(창).
> 테스트: `tests/test_charswap.py <게임 폴더> <작업 폴더> [모델 파일]`.

## 1. 하는 일

FBX·VRM·glTF 같은 모델 파일 하나를 골라 **아일렛 플레이어 캐릭터(여자 F1·남자 M1)와 사람 NPC** 대신 쓰는 모드를
만든다. 게임의 걷기·달리기·점프·채집·춤 등 **아일렛 애니메이션을 그대로** 쓴다.

| 형식 | 읽는 방법 |
|---|---|
| `.fbx` (바이너리 7.x, ASCII 7.x) | 내장 (Blender 불필요). 3ds Max Biped·Mixamo·Unity 등 |
| `.glb` `.gltf` `.vrm` (VRM 0.x / 1.0) | 내장. VRM은 파일 안의 휴머노이드 뼈 지도를 그대로 씀 |
| `.pmx` (MMD) | 내장. 일본어 뼈 이름(腕·ひじ·手首·足·ひざ…) 인식 |
| `.obj` (+`.mtl`) | 내장. 뼈대가 없어서 몸 전체가 골반에 붙음(팔다리 안 움직임) |
| `.dae` `.3ds` `.blend` `.usd*` `.abc` `.ply` `.stl` `.x3d` `.wrl` | 설치된 **Blender**로 glb 변환 후 읽음 (경로 자동 탐색 또는 지정) |

텍스처는 파일에 들어 있거나(FBX Video, glb) 모델 옆 폴더에서 이름으로 찾는다. 못 찾으면 폴더에 그림이 하나뿐일 때 그 그림을 쓴다.

## 2. 왜 그냥 붙이면 안 되나 → 리타깃

아일렛 캐릭터는 2등신(머리 0.85, 다리 0.46)이고, 애니메이션 키는 뼈의 **로컬** 위치·회전이다. 다른 비율의 모델을
아일렛 뼈에 그대로 스키닝하면 팔꿈치가 아일렛 팔꿈치 위치를 축으로 돌아 몸이 찢어진다. 그래서:

1. **정규화** — +Y 위, 엔진의 −Z 정면(왼쪽이 +X), 발바닥 y=0, 골반 x=z=0, 키 = 원래 캐릭터 키(F1 1.894, M1 1.769)로
   맞춘 뒤 엔진의 왼손 좌표계로 미러. 위쪽·정면은 뼈(머리−골반, 왼쪽−오른쪽 다리/팔)로 자동 판단, `turn`으로 수동 보정.
2. **뼈 찾기** — 이름 규칙(Biped, Mixamo, VRoid `J_Bip_`, Unity/UE `upperarm_l`, Rigify `DEF-…​.L`, CC `CC_Base_`,
   MMD 일본어)으로 손·발·머리를 찾고 계층을 따라 올라가며 팔·다리·쇄골·목, 척추 사슬, 손가락, 트위스트 뼈를 정한다.
3. **자세 맞추기** — 모델의 위팔·아래팔·손·허벅지·종아리를 아일렛 바인드 포즈 방향(팔 38° 아래로 벌린 A자세)으로 돌린다
   (모델 자체의 스킨 가중치로 메시를 변형). 발은 원래 방향을 유지(발바닥 평평).
   - `arm_angle`(기본 12°): 2등신은 둥근 배 때문에 팔을 벌리고 있어서, 날씬한 모델은 같은 각도면 날갯짓처럼 보인다 → 몸쪽으로.
   - `leg_angle`(기본 자동): 아일렛 대기 자세는 발을 7° 안쪽으로 모으는데 엉덩이 폭/다리 길이 비가 다르면 다리가 꼬인다 →
     발 간격 비율이 같아지게 바깥으로 벌림 (유이: 5.1°).
4. **새 스켈레톤** — 아일렛 뼈 31/29개의 번호·이름·바인드 **방향**은 그대로, 관절 **위치**만 모델의 관절로. 손가락이 없는
   뼈(Finger0/1·Toe0·Xtra01/02·Footsteps)는 원래 오프셋을 비율대로. `ForeTwist`는 아래팔 관절. 헬퍼(`Point_Hand_R` 등
   도구가 붙는 점)도 같이 옮긴다.
5. **가중치** — 모델 뼈 → 아일렛 뼈. 엄지 → Finger0, 나머지 손가락 → Finger1, 머리카락·눈·장신구 → 가장 가까운 상위 뼈,
   골반에 붙은 치마·꼬리 뼈는 골반과 허벅지에 섞어서(무릎 쪽일수록 허벅지 65%까지) 다리를 들 때 치마가 따라온다.
   정점당 4개, 엔진 셰이더가 4번째 가중치를 `1 − (w0+w1+w2)`로 계산하므로 앞 3개를 정확히 맞춘다. 루트(Bip001)에는
   가중치를 주지 않는다(엔진이 부모 없는 뼈의 스킨 행렬을 단위행렬로 둠).
6. **애니메이션** — 회전·스케일 키, 메시 트랙, 태그·사운드·이펙트는 **바이트 그대로**. 위치 키만:
   루트(Bip001)·Footsteps는 `× 엉덩이 높이 비`(유이 2.1배: 웅크림·점프·달리기 출렁임이 긴 다리에 맞음),
   나머지 뼈는 `새 뼈 길이 + (원래 키 − 원래 뼈 길이) × 비율`.

확인: 아일렛 캐릭터 자신을 glTF로 내보내 다시 교체하면 관절·위치 키가 원래대로 돌아오고(0.02 이내), 다른 성별 뼈대에
붙여도 모든 프레임에서 팔·다리 방향이 원래 애니메이션과 같다(`tests/test_charswap.py`). 내장 FBX 읽기는 같은 파일을
Blender 4.2로 읽은 결과와 정점 0.000006 이내로 같다.

## 3. 모드에 들어가는 파일

| 파일 | 내용 |
|---|---|
| `Character\F1\f1.nwbt`, `Character\M1\m1.nwbt` | 새 관절 위치의 스켈레톤 |
| `Item\Default\f1_body01.nwmt`, `m1_body01.nwmt` | 교체 모델 (기본 몸 아이템 #300이 항상 입는 파츠) |
| `Character\F1\*.nwat`, `Character\M1\*.nwat` | 모든 캐릭터 애니메이션 (110개씩) |
| `Item\Default\cs_<이름>.png` (+`_mask`, `_spec`) | 모델 텍스처, 검은 마스크(피부·머리 색 물들이기 끔), 검은 스페큘러 |
| 얼굴·머리·옷·신발·장갑·모자·등·장신구 `f1_*`/`m1_*` (약 1,380개) | 보이지 않게 줄인 버전: 재질·메시 번호·헬퍼는 그대로, 메시마다 넓이 0 삼각형 하나, 머리카락 물리 제거. 얼굴 표정 텍스처를 재질 번호로 바꾸는 코드가 있어서 지우지 않고 줄인다 |
| `npc\human\…` | 사람 NPC의 스켈레톤·모델·애니메이션 (같은 옷·머리를 입으므로 같이 교체) |

프로젝트의 `charswap.json`이 쓴 파일 목록을 기억한다. 다시 실행하면 이전 교체를 지우고 새로 쓰며, **교체 되돌리기**
(`character_swap_remove`)는 교체가 쓴 파일을 지우고 그 전에 프로젝트에 있던 파일(`.charswap_backup`)을 되살린다.
게임에 넣는 것은 다른 모드와 같다: 모드 관리자에서 설치 → 적용 (원본 복구로 되돌림).

## 4. 한계 (알고 쓰기)

- **게임에서 확인함 (2026-10-15)**: 히라사와 유이 FBX(3ds Max Biped, 정점 8,457개)로 여자·남자 캐릭터와 사람 NPC를 바꿔 모드 관리자로 적용 → 게임에서 정상 동작. 다른 모델·형식은 같은 경로를 쓰지만 모델마다 미리보기로 확인할 것.
- 의자·침대: 아일렛 동작은 골반을 좌석 높이에 두므로, 다리가 긴 모델은 발이 바닥 아래로 들어간다.
- 모자·안경·등 장식·옷을 입어도 보이지 않는다(모델이 자기 옷을 입고 있음). 손에 드는 도구는 그대로 보인다.
- 표정(눈 깜빡임·입 모양)은 아일렛 얼굴 텍스처로 하던 것이라 교체 모델에는 없다. 피부·머리 색 고르기도 적용되지 않는다.
- 이름표·카메라 높이는 엔진이 정하는 대로다.
- 다른 플레이어 화면에는 그 사람이 설치한 모드대로 보인다(내 PC에서만 바뀜).
- 모드 안의 애니메이션은 게임 원본을 고친 것이고 모델은 만든 사람의 작품이다: 모드 zip을 공개 배포하지 말고,
  모델 배포 조건을 확인할 것.
