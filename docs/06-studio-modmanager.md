# NarewStudio · NarewModManager 사용 설명서

두 프로그램은 역할이 나뉘어 있다. 둘 다 **네이티브 Windows 프로그램**(Qt 6 + OpenGL 3.3)이다. 웹 브라우저나 WebView는 쓰지 않는다.

| 프로그램 | 하는 일 | 게임 폴더 |
|---|---|---|
| **NarewStudio** (모딩 툴) | 리소스 편집, 블록·가구 텍스처, **새 블록·가구·아이템·사운드 추가**, 월드 에디터, 모델 뷰어, 팩 탐색기 → 결과를 "모드"로 저장 | **읽기만** 함 |
| **NarewModManager** (모드 매니저) | 모드 설치·켜기/끄기·우선순위 → 게임에 적용 / 원본 복구 | 적용할 때만 씀 |

실행: `dist\NarewTools\NarewStudio.exe`, `dist\NarewTools\NarewModManager.exe` (설치 불필요. 두 exe가 한 폴더의 Qt를 같이 쓰므로
폴더째 옮긴다). 배포용 묶음은 `dist\NarewTools-<버전>.zip`.
소스에서 실행: `python -m studio`, `python -m modmanager` (Python 3.10+, `pip install PySide6 moderngl numpy pillow`).
필요 사양: OpenGL 3.3을 지원하는 그래픽 드라이버 (3D 화면만 해당. 없으면 3D 창에 안내가 뜨고 나머지 기능은 그대로 쓸 수 있다).

## 1. 모드 형식 (버전 2)

```
내모드/
  mod.json        {"id": "pastel-blocks", "name": "파스텔 블록", "version": "1.0.0", "author": "", "description": "", "format": 2}
  preview.png     (선택) 목록에 보일 그림
  files/          통째로 바꾸거나 새로 넣는 파일. 게임 팩 안의 경로 그대로 (대소문자 무시)
    terrain.png
    Item/Icon/brick/icon_brick_149.png
  merge/          게임 표(XML)에 "항목 단위"로 더하거나 바꾸는 패치
    XML/item_table.xml
    XML/brick_table.xml
    Language/string.xml
```

- `files/`는 파일 전체를 바꾼다. 같은 파일을 바꾸는 모드가 둘이면 우선순위가 높은 쪽만 들어간다.
- `merge/`는 표의 **항목(레코드) 하나하나**를 더하거나 바꾼다. 그래서 여러 모드가 같은 표(아이템 표, 문자열 표 등)에 각자 항목을
  추가해도 모두 들어간다. 형식과 엔진 한도는 [새 콘텐츠 추가](07-new-content.md) 참고.
- 배포는 이 폴더를 zip으로 묶은 파일이다 (NarewStudio의 "배포용 .zip 만들기"). 원본 게임 파일을 통째로 배포하지 말고 바꾼 것만 담는다.

## 2. NarewStudio

처음 실행하면 게임 폴더를 고르고, 위쪽 **새 모드**로 모드 프로젝트를 만든다 (기본 위치 `문서\NarewStudio\Projects`).
수정한 파일은 모두 프로젝트에 저장되고 게임 파일은 바뀌지 않는다. 모드 매니저가 이미 적용한 팩·파일은 `.orig` 백업에서 원본을 읽는다.
화면에 보이는 표(XML)는 "게임 원본 + 이 모드의 merge 패치"를 합친 결과다.

### 2.2 월드 캡처 (지금 하는 월드를 .bwr로 저장)

내 PC에서 여는 월드(싱글 플레이, 내가 연 서버)는 게임이 `Local\<월드>.bwr`에 저장해 둔다(docs/05 3.5). 월드 캡처는 그 저장본을
`문서\NarewStudio\Worlds\<월드>_<날짜>_<게임이 저장한 시각>.bwr`로 복사한다(같이 저장된 `.lnd`·`.npc`도 함께).

- 월드 에디터의 "📸 현재 월드 저장", 또는 "캡처 창": 항상 위에 떠 있는 작은 창.
  - **Ctrl+Alt+S**: 게임 화면에서도 눌러 저장(소리로 알림). 다른 프로그램이 이 단축키를 쓰면 창에 표시된다.
  - "게임이 저장할 때마다 자동으로 남기기": 게임이 저장 파일을 새로 쓸 때마다 한 벌씩 남긴다.
  - 게임하면서 이 창만 띄우려면 `NarewStudio.exe --capture`.
- 저장되는 것은 **게임이 마지막으로 저장한 상태**다. 게임 안에 코드를 넣지 않으므로 아직 저장되지 않은 변경은 담기지 않는다.
- 같은 저장본을 두 번 캡처하면 새 파일을 만들지 않는다. 게임이 쓰는 중이면 다 쓸 때까지 기다렸다가 읽는다.
- 다른 사람이 연 서버의 월드는 내 PC에 없으므로 캡처할 수 없다(그 서버 주인이 `.bwr`를 주면 에디터로 열 수 있다).

### 2.3 내 월드에 적용 (고친 맵을 게임에 넣기)

1. "💾 내 월드"에서 게임 저장본(`Local\<월드>.bwr`)을 열고 고친 뒤 "저장" → 새 파일(`문서\NarewStudio\Worlds\…`).
2. 그 파일을 연 상태에서 **🎮 내 월드에 적용** → 게임의 `Local\<월드>.bwr`을 이 파일로 바꾼다.

- 먼저 지금 저장본(`.bwr .lnd .npc .db`)을 `문서\NarewStudio\WorldBackups\<월드>_<시각>\`에 백업한다(Steam 클라우드가 동기화하는 `Local\` 밖). **↩ 백업으로**로 언제든 되돌린다(되돌리기 전 상태도 백업).
- 게임이 켜져 있으면 하지 않는다(게임이 다시 덮어씀). 크기가 다른 월드는 넣지 않는다(`.lnd`가 월드 크기에 맞춰져 있음).
- 고친 파일보다 게임이 나중에 저장했으면 경고한다(적용하면 그 뒤 진행이 사라짐 — 백업에는 남음).
- 이 월드의 높이 규칙: 바닥 블록(#60)이 0층, 그 위 1층이 걸어 다니는 바닥 높이이고 설치물은 2층에 놓인다(게임이 직접 놓은 의자·상자와 같음).

**Blender 작업 팁** (docs/04 6장): 가져오기 전에 장면을 30fps로, 내보낼 때 Include → Custom Properties를 켠다.

## 3. NarewModManager

1. 게임 폴더를 고른다.
2. 모드를 설치한다: zip을 창에 끌어다 놓기 / "＋ .zip 설치…" / "폴더에서 설치…" / NarewStudio의 "모드 매니저에 설치".
3. 체크로 켜고, 끌거나 ▲▼로 우선순위를 정한다 (위가 우선). 오른쪽에서 모드의 파일·표 병합과 다른 모드에 가려지는 파일을 확인한다.
4. **게임을 끈 상태에서** "게임에 적용". 되돌리려면 "원본 복구".

적용 방식:

| 방식 | 동작 | 상태 |
|---|---|---|
| 팩 패치 (기본) | 원본 팩을 처음 한 번 `data\<팩>.pack.orig`로 보관하고, 적용할 때마다 그 원본 + 켜진 모드로 팩을 새로 만든다. 안 바뀐 파일은 재압축 없이 그대로 복사 | 인게임 확인됨 (팩 로드) |
| 낱개 파일 (실험적) | 모든 모드 파일을 게임 폴더에 낱개로 둔다. 팩을 건드리지 않음 | GUI 이미지만 인게임 확인됨 |

- **표 병합**: 표마다 "모드가 통째로 바꾼 파일(있으면) 또는 게임 원본"을 바탕으로, 켜진 모드의 `merge/` 패치를 우선순위 낮은 것부터
  차례로 적용한다. 같은 항목을 두 모드가 고치면 위쪽 모드가 이긴다. 원본의 인코딩(EUC-KR 등)·줄바꿈은 그대로 유지한다.
- 팩에 없는 새 파일은 게임 폴더에 낱개 파일로 둔다. 모드 매니저가 만든 파일만 기록해 두고 지운다.
- 게임 폴더에 원래 낱개로 있는 데이터 파일(`Language\string.xml` 등)을 바꿔야 하면 처음 한 번 `<파일>.orig`로 백업하고 바꾼다.
  "원본 복구"가 백업을 되돌린다. 실행 파일·DLL·팩, 게임 폴더 맨 위의 파일은 절대 덮어쓰지 않는다.
- Steam 업데이트나 "게임 파일 무결성 확인"으로 팩·파일이 바뀌면 다음 실행 때 감지해서 오래된 백업을 버리고(새 파일이 원본) "다시 적용"을 안내한다.
- 기록 위치: `%LOCALAPPDATA%\NarewModManager\` (`mods\`, `settings.json`, `deployed.json`, 오류 로그 `log.txt`).

### 3.1 자동 업데이트 (두 프로그램 공통, 2.2.0부터)

- 켤 때 GitHub 최신 릴리스(`cailet0422/NarewTools`, 초안·사전 릴리스 제외)를 확인한다. 자동 확인은 6시간에 한 번이고, 알림 창의
  "프로그램을 켤 때 업데이트 확인"으로 끈다. 머리줄 오른쪽 버전 버튼(`v2.2.0`)은 바로 확인한다.
- 새 버전이면 바뀐 점(릴리스 설명)과 함께 업데이트 / 나중에 / 이 버전 건너뛰기를 묻는다.
- 업데이트: 릴리스의 `NarewTools-<버전>.zip`을 받아 같은 릴리스의 `.zip.sha256`으로 확인하고
  `%LOCALAPPDATA%\NarewTools\update\<버전>\`에 푼다(폴더 밖을 가리키는 경로는 거부). 받은 주소는 이 저장소의 릴리스 다운로드만 허용한다.
- 프로그램을 닫으면(지금 닫기를 고르거나 나중에 직접 닫을 때) **새 버전의** NarewAgent.exe가 푼 폴더에서 실행되어
  `--apply-update`로 교체한다: 이 폴더에서 실행 중인 NarewTools 프로그램이 모두 끝나기를 기다리고(최대 2분), 바꿀 파일을
  `update\backup-<이전 버전>\`에 백업한 뒤 새 파일을 복사한다. 하나라도 실패하면 백업으로 되돌린다. 끝나면 프로그램을 다시 켜고,
  결과(성공·실패와 이유, 기록 `update.log`)를 다음 실행 때 알린다. 사용자가 폴더에 넣은 파일은 지우지 않는다.
- 소스에서 실행(`python -m studio`)하면 확인만 하고 바꾸지 않는다(git pull 안내). 쓸 수 없는 폴더(`Program Files` 등)는 받기 전에 알린다.
- 설정·마지막 결과: `%APPDATA%\NarewTools\update.json`. 2.1.0 이하에는 이 기능이 없으므로 2.2.0은 한 번 직접 받아 폴더를 바꾼다.

## 5. 알려진 한계

- 새 블록·가구와 UI 효과음 교체는 2026-10-13 게임에서 동작을 확인했다. "새 아이템"으로 만든 일반 아이템의 효과, 날씨·시간 배경음,
  멀티 플레이는 아직 따로 확인하지 않았다 (docs/07 5장).
- 블록 면 이름(앞/뒤)과 게임 좌표 z 방향의 대응은 추론이다(대부분의 블록은 6면이 같아 영향이 작다).
- 월드 에디터의 설치물 놓기는 표지판·사진·영상·텃밭·자동 제작·풍차·상점·우편함(자체 데이터가 필요한 80종)을 아직 지원하지 않는다. 이미 놓인 설치물의 이동은 지우고 다시 놓는 방식이다(돌리기와 조명 켜기/끄기는 "✋ 설치물 편집"으로 제자리에서). 월드 편집(블록·설치물)과 "내 월드에 적용"은 2026-10-14 인게임 확인됨.
- 프리팹 일부가 쓰는 블록 ID 171–191은 표에 없어 자홍색으로 보인다(docs/05 4장). 새 블록 번호로도 쓰지 않는다.
- 모델 가져오기는 원본을 틀(template)로 쓰므로, 메시 구성이 크게 다르면 일부 정보가 원본 값으로 남을 수 있다(docs/04 8장).
